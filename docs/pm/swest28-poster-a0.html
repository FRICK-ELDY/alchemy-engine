分散連合型VRプラットフォームの開発と研究

Development and Research of a Distributed Federated VR Platform
FRICK-LAB 松尾 英樹

概要

個人や組織が自分のドメインで VR 空間を運営し、 インスタンス同士が連合できる 分散連合型 VR プラットフォーム AlchemyEngine の開発と研究について報告する。

既存の VR プラットフォームの多くは、単一運営者による 閉じたサービス か、特定エンジン前提の実装である。 テキスト SNS では Mastodon や Misskey のように セルフホストと連合が成立しているが、 3D 空間とリアルタイム同期 を対象にした 同様の基盤はまだ少ない。

AlchemyEngine は、エンジンが保証するものを 「無限の3D空間」 と 「そこに存在するユーザー」 に限定する。 空間の上に何を置くか——機器、資料、3D モデル、通信の可視化、体験——は すべて コンテンツ であり、 利用者がコンポーネントとして持ち込む。

エンジンが保証するもの
  • 無限の3D空間 — f64 精度の座標系
  • ユーザーの存在 — 位置・向きを持つプレイヤー
  • ネットワーク基盤 — 複数ユーザーが同じ空間を共有
  • 時間の流れ — サーバー側の権威 tick（20Hz）
  • コンテンツのライフサイクル — Scenes / Objects / Components の契約

空間の正しい状態と時間の進み方は サーバー（Elixir / OTP） が決め、 描画・入力・予測補間は Rust クライアント が担う。 最終的には alchemy.{ドメイン} のように 各運営者がインスタンスを立て、 合意したプロトコルで空間・ユーザーのアイデンティティ・コンテンツを 連合 させることを目指す。

解決したい事

中央集権型のプラットフォームでは、 運営・規約・管轄が一つのサービスに集約される。
表現として優れた作品でも、運営者の都合で一方的にはじかれうる。
居場所が借り物だと、文化やマーケットの存続がホスト側の裁量に依存する。

そこで 分散連合型 にする。 分散は、個人が自分のインスタンスを立てて運営できること。
連合は、インスタンス同士が後からつながれること。
プラットフォーム運営を特定サービスに任せず、個人に委ねる設計が意図である。

中央集権型 分散連合型
運営 一つのサービスに集約 個人がインスタンスを運営
規約・管轄 ホスト側の裁量 立てた側が担う
居場所 借り物（追い出されうる） 自前ホスト
他空間との関係 サービス内に閉じる 連合で後からつなぐ

テキスト SNS の Mastodon や Misskey のように、3D 空間でもこの二層を土台にしたい。
本発表では、まず分散側の最小単位を解く。

  • サーバー（Elixir）が空間の正しい状態を持つ
  • 複数クライアント（Windows / Mac）がその状態を同じ描画で見る
  • 外部入力（OSC）もサーバー経由で空間に入り、全クライアントに届く

※ 連合は次の段階。 今日は「1 インスタンスを自前ホストで共有できるか」に集中する。

実証デモ

異種端末・同一ルームで、同じ 3D 空間の描画が揃うことを示す。
iPhone のテザリングで Windows / Mac を同一ネットワークにし、
OSC 入力がサーバー経由で両クライアントに反映されることを確認する。

手順の要点

  • iPhone テザリングで Windows と Mac を同じネットワークに置く
  • Windows：mix alchemy.router → server → client
  • Mac：mix alchemy.client --connect tcp/<ip>:7447（Windows の main room）
  • LittleOSC から Windows server へ OSC 送信

成功の見方

  • OSC の操作が Windows 側の空間に反映される
  • 同じ変化が Mac クライアントの描画にも現れる
  • → サーバー権威の状態が、Zenoh 経由で複数端末に同期できている

今後

現状できているのは、1 運営者の単一インスタンスのなかで、 Elixir サーバーが空間の正しい状態を持ち、Zenoh 経由で複数クライアント （異種 OS 含む）へ同じ描画を同期し、OSC などの外部入力もサーバー経由で空間に載せることである。

AlchemyEngine は最終的に、各運営者が alchemy.{ドメイン} のようにインスタンスを立て、
合意プロトコルで空間・ユーザーのアイデンティティ・コンテンツを連合させることを目指す。

これから進めること

  • 認証とアセットの追加
  • 運営者間の連合（S2S / ポリシー / ユーザーのアイデンティティ）
  • 空間・コンテンツの一覧（Hub）
  • ヘッドセット向け VR 入力（OpenXR）の本格化
  • contents 層（Scenes / Objects / Components / Nodes）の拡充
